# FluentYTDL 适配边界

公开仓库仅发布核心；FluentYTDL 应用源码、账号、配置、POT Token、原始网络日志均不公开。

## 替换位置

关闭应用并备份原核心。开发目录通常为 `assets/bin/yt-dlp/yt-dlp.exe`，已打包应用为 `bin/yt-dlp/yt-dlp.exe`；用户指定的自定义核心路径优先，应确认应用实际选择的路径。核对 SHA256 后替换为同名文件，保留相邻插件目录。

正式版直接替换可继续走原有 CLI，但应用自身更新/重装/修复可能覆盖核心。`-U` 禁用只控制 EXE 自更新。固定测试包需在应用的检查、安装与更新执行入口保护 yt-dlp，并继续允许其他组件更新；不要全局关闭 POT/Deno/FFmpeg 更新。旧版应用可能无法解析含斜杠的仓库 channel，显示“未知版本”不等于 EXE 不能运行。

## 本地验收范围

1. 记录应用版本、EXE SHA256、上游 SHA；确认版本探测与下载调用使用同一个文件。
2. 使用原 POT 插件、Provider、Deno、FFmpeg，检查普通解析与显式 SABR 音视频下载及合并播放。
3. 检查格式筛选保留 protocol、format_id、语言与音视频分离信息；不强制所有任务走 SABR。
4. 检查并行音视频进度、取消、暂停恢复与 SABR 状态文件进入既有 staging 生命周期，成功只在文件验证和提交完成后发出。
5. 保留旧核心的 SABR-only 客户端回退；新核心存在可下载 SABR 格式时不得因旧启发式反复重解析或强制切换客户端。
6. [PR 当前说明](https://github.com/yt-dlp/yt-dlp/pull/13515)列明功能限制：分段下载、限速、并发分片选项不能假定与普通协议一致；按选中协议判断，必要时选择可用的普通协议，或明确提示不支持。不得将请求片段静默变成完整视频下载。
7. 字幕、封面、播放列表、VR、多语言与 GUI 操作需要分别回归，核心测试不替代这些验收。

首次发布的 CI 验证与后续本地在线验证分开记录；未测试场景保留为未验证。自动发布的新 revision 不自动继承旧 revision 的兼容性结论。
